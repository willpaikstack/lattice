## Status Key

- `Operational` - uses real app workflow data and is expected to work in local development when required services are configured.
- `Partial` - visible and useful, but still missing durable persistence, production storage, ownership checks, external service configuration, or other hardening.
- `Prototype` - useful as a design/product reference, but still partly static, local-only, or not the final workflow.
- `Placeholder` - route or module exists, but the feature is intentionally future-facing.

## Product Model

Lattice OS is a manufacturing RFQ, procurement, and supplier-network operating system. The app is organized around four spaces:

- Public access-request intake for prospects.
- Customer workspace for RFQs, quotes, orders, resources, and notifications.
- Admin workspace for internal RFQ review, quote issuance, customer/vendor management, orders, and documents.
- Supplier workspace for supplier order visibility and invoice access.

The current source-of-truth workflow is `Request`/`LatticeRequest`: a buyer submits an RFQ, Lattice reviews it, admin issues a quote, the buyer accepts or checks out, and the purchased request becomes an order.

## Customer Workspace

Quote configuration update (2026-10-15): RFQ submission is available only through the Request Quote button's click handler. Implicit form submission and Enter activation of that button are blocked; dropdown keyboard selection and multiline notes still work. A different intended-use part's separate-quote warning explains that the current quote remains saved as a draft and the new quote opens in another tab. Per-part customer arrival preferences are labeled Target delivery date and stored as `manufacturingDetails.targetDeliveryDate` (YYYY-MM-DD), including draft restoration, validation, submission, admin detail and quotation workbench. Legacy `targetShipDate` keys remain readable and are normalized to the new schema without losing dates; an idempotent SQL backfill renames existing submitted-part keys.


Customer CAD intake now accepts STL, OBJ, glTF and GLB in addition to the existing STEP/IGES and native CAD formats. STEP/STP, IGES/IGS, STL, OBJ and self-contained glTF/GLB now render locally in the customer RFQ form, reopened drafts, customer quote detail (View 3D) and admin RFQ review. Native SLDPRT, SAT, Parasolid and IPT continue through Autodesk. Local preview errors preserve the original and do not fall back to Autodesk. The demo and all supported RFQ CAD/drawing formats share the existing 200 MiB per-file cap; display labels say 200 MB. Local conversion runs in cancellable workers, serialized one at a time, and mesh buffers transfer without copying. Saved local previews use the authorized same-origin original-file stream, never a public storage URL. Geometry bounds for STL/OBJ remain unitless; no millimeter metadata is invented. Local model cards use an on-demand View 3D control rather than requesting APS thumbnails.
